# Network Observability Showcase: shared brief for dashboard lanes

Audience: a network team migrating from LogicMonitor. FRAMING: the dashboards present a
production-like environment for a single customer operating a massive global network (one
enterprise DC, a global Clos core with WAN, five regional spoke sites, server fleet, external
probes). Write every title, description and text panel as that customer's production NOC would:
never say "demo", "showcase", "art of the possible", "synthetic", "synthkit" or "fake" anywhere in
the dashboards. Do not name a real company; refer to "the estate" / "global network". Every
dashboard must look polished, use a variety of panel types, and be driven ONLY by real series that
exist on the stack today. No hard-coded numbers dressed up as live data.

## Target

- gcx context: `<target-stack>` (Grafana Cloud, Grafana 12, dashboards API `dashboard.grafana.app`).
- Folder UID: `netobs-showcase` (title "Network Observability Showcase"). It already exists. Put the
  folder on each dashboard with `metadata.annotations["grafana.app/folder"]: netobs-showcase`;
  `spec.folderUID` is ignored.
- Datasources: Prometheus uid `grafanacloud-prom`, Loki uid `grafanacloud-logs`. Always set the
  datasource uid explicitly on every panel and query (the stack has several Loki datasources and an
  unset one silently renders "No data").
- Data is synthetic, generated by synthkit, and only exists from when the generator started. It is forward-only: use time ranges like `now-1h` / `now-3h`, never days.
- Tag every dashboard `netobs-showcase` (an internal grouping tag; it is never shown as a title) and add a dashboard link (type dashboards, tag
  `netobs-showcase`, asDropdown) so they cross-link.

## Panel plugins installed on the stack

Built-ins (nodeGraph, geomap, canvas, state-timeline, status-history, heatmap, bargauge, gauge,
table, piechart, barchart, xychart, trend, histogram, logs, text, stat, timeseries) plus:
`esnet-networkmap-panel`, `tamirsuliman-weathermap-panel`, `andrewbmchugh-flow-panel`,
`volkovlabs-echarts-panel` (Business Charts), `grafana-polystat-panel`, `netsage-sankey-panel`,
`esnet-matrix-panel`, `marcusolsson-dynamictext-panel` (Business Text),
`taminomara-hostoverview-panel`, `orchestracities-map-panel`, `grafana-clock-panel`,
`marcusolsson-treemap-panel`.

Look up each plugin's options schema from its current README/source before using it (grafana.com
plugin page or its GitHub repo; Firecrawl `firecrawl_scrape` or WebFetch). Do not guess options.
Known findings from an earlier build:
- Flow panel: SVG cell `id` must equal the series legend (set `legendFormat: "{{device_id}}"`);
  panelConfig YAML maps cellId -> dataRef -> thresholds.
- Business Charts: the JS reads `context.panel.data.series[N].fields[]` (`.name`, `.values`), not
  `context.data`; use instant `format: table` queries; the ECharts `graph` series uses `links`.
- Built-in nodeGraph needs string `id`/`source`/`target` columns plus an `id` on edges: build them
  with `label_join` in PromQL, use two instant table queries (nodes and edges), and organize away
  the `Value #A`/`Value #B` columns. Working example: dashboard uid `netobs-topology`.

## Data on the stack (all Prometheus unless noted)

### SNMP topology discovery exporter (`job="integrations/network-topology-exporter"`)

Contract: `signals/nettopo.md` (read it). Three exporters, label `instance`:
- `netobs-ent-dc1:9100` enterprise DC, site `hq-dc1`: 33 devices / 38 links (edge-fw-01 -BGP->
  spine-01/02 -LLDP-> leaf-01..06 -> 24 host-leafNN-MM). Standalone.
- `netobs-glb-hub:9100` global federation hub, site `global`: ~128 devices / ~243 links, 6-spine x
  24-leaf Clos, vendors arista/cisco/juniper/nokia, wan-core devices, ext-peer boundaries,
  protocols lldp/fdb/bgp/mpls_te. Spokes `dc-amer dc-apac dc-emea dc-edge-1 dc-edge-2`
  (label `spoke_id`).
- `netobs-spoke-emea:9100` EMEA spoke, site `emea-edge1`: 9 devices / 8 links.

Key series:
- `network_topology_device_info{device_id,vendor,os_version,site}` = 1 (no model label, no role
  label: derive tier from the device_id prefix: edge-fw/wan-core/spine/leaf/host/ext-peer).
- `network_topology_device_uptime_seconds{device_id}`.
- `network_topology_edge_info{src_device,src_port,dst_device,dst_port,discovery_proto,link_kind,direction}` = 1.
  discovery_proto in lldp|cdp|bgp|ospf|fdb|isis|mpls_te; link_kind ethernet|ip|mpls-te.
- `network_topology_graph_devices_total`, `_graph_edges_total`, `_graph_stale`,
  `_out_of_scope_neighbours_total` (per instance).
- `network_topology_change_total{change_kind,discovery_proto}` (counter, use increase()).
- `network_topology_module_last_status{module}` 0 ok / 1 degraded / 2 hard-failed.
- `network_topology_discovery_cycle_duration_seconds_bucket`, `_discovery_module_duration_seconds_bucket{module}` (classic histograms).
- `network_topology_snmp_walks_total{status,reason}`, `_walker_outcome_total{walker,outcome}`,
  `_bgp_walker_outcome_total{walker,outcome}`, `_credential_trials_total{status}`,
  `_snmp_session_pool_*`, `_snmp_rate_limit_wait_seconds_bucket`.
- Federation: `network_topology_federation_spoke_up{spoke_id}`,
  `_federation_spoke_last_push_timestamp_seconds{spoke_id}`, `_graph_updates_rejected_total{reason}`,
  `_boundary_observation_info{peer_a,peer_b,reporting_device,src_port,proto}`, spoke-side
  `_federation_spoke_push_*`.
- Loki: `{source="network-topology-exporter"}` topology change lines (logfmt: event=topology_change
  change_kind proto src_device src_port dst_device dst_port direction) and conflict lines
  (event=topology_conflict conflict_type=neighbour_disagreement). Stream labels: source, instance,
  job, change_kind, discovery_proto / conflict_type.

Per-device health does NOT exist (change/module/discovery families carry no device_id). Do not
invent per-device link utilisation. Per-link traffic does not exist in the topology data.

### Host interface metrics (hostfleet blueprint, node_exporter style)

`node_network_{receive,transmit}_{bytes,packets,errs,drop,fifo,compressed}_total`,
`node_network_receive_multicast_total`, `node_network_up`, `node_network_carrier`,
`node_network_speed_bytes`, `node_network_mtu_bytes`, `node_network_info`,
`node_network_transmit_queue_length`. Hosts (label `instance`): hfleet-linux01, hfleet-linux02,
hfleet-ci01, hfleet-pve01 (job `integrations/node_exporter`, device eth0) and hfleet-mac01 (job
`integrations/macos-node`, en0). Windows hosts may emit `windows_net_*`. Other node_* families
(cpu, memory, filesystem) also exist. Contract: `signals/host.md`.

### Synthetic probes (synthetic-checks blueprint)

`probe_success`, `probe_duration_seconds`, `probe_all_duration_seconds_bucket`, `sm_check_info`
(labels check_name, region, frequency, geohash), per probe `synmon-*` HTTP checks from probes
`synthkit-private-emea`, `synthkit-private-us`, `synthkit-private` in regions EMEA/US/APAC.
Loki `{source="synthetic-monitoring-agent"}`. Contract: `signals/sm.md`.

Before relying on any series, query it live: `GCX_AGENT_MODE=true gcx --context <target-stack> metrics query -d grafanacloud-prom '<promql>'`
and for logs `gcx --context <target-stack> logs query -d grafanacloud-logs '<logql>' --since 30m`.

## How to build and verify

1. Write a Python generator `dashboards/showcase/netobs/<uid>.gen.py` (stdlib only; it writes
   `<uid>.json` beside itself via `os.path.join(os.path.dirname(os.path.abspath(__file__)), ...)`;
   see the existing `*.gen.py` for style). The generator is the source; never hand-edit the JSON.
   The output is a dashboard resource (apiVersion
   `dashboard.grafana.app/v1beta1` with a classic `spec` is the most plugin-friendly; v2 is fine
   too). Use your own uid prefix `nos-<lane>`; only touch your own files.
2. `GCX_AGENT_MODE=true gcx --context <target-stack> resources validate -p <file>` then `resources push -p <file>`.
3. Snapshot: `GCX_AGENT_MODE=true gcx dashboards snapshot <uid> --context <target-stack> --output-dir snapshots/<uid> --since 1h --width 1920 --theme dark`
   (check `--help`; `--var name=value` sets variables). READ every PNG and fix what you see:
   "No data", plugin errors, clipped diagrams, overlapping labels, unreadable colours. Iterate until
   it genuinely looks good. A clean push proves only that JSON parsed.
4. The `gcx:create-dashboard` skill has the gcx dashboard workflow if useful.

## Rules

- Do not touch other lanes' files, the synthkit Go code, blueprints, or any Grafana resource outside
  your own dashboard uids. Do not install plugins or change datasources. Never commit.
- No em dashes or en dashes in any title or text; use " - ".
- Every text/markdown panel must be accurate about what a panel shows and which metric drives it,
  written in production-NOC voice (see FRAMING): no "demo", "synthetic" or "showcase" wording.
- If you hit a decision this brief does not cover, stop and return the question.
- Final message: the complete report: uids, titles, URL path `/d/<uid>`, panel list with panel type
  and driving query, what you verified in the snapshots (PNG paths), and anything left imperfect.

## Live estate behaviour (added after the first wave)

- Background faults recur on schedules: `nettopo_devices_unreachable` (devices vanish from
  device_info/device_uptime_seconds for a few minutes: ent-dc1 every 53m for 4m, hub every 41m
  for 3m, spoke every 71m for 5m), `nettopo_walker_degraded`, `nettopo_discovery_slow`
  (graph_stale=1), `nettopo_auth_failures`, and the hub's hourly `nettopo_spoke_down`. Detect an
  unreachable device as "seen in the last hour but absent now":
  `max by (instance, device_id) (last_over_time(network_topology_device_info[1h])) unless on (instance, device_id) network_topology_device_info`.
- Synthetic probes are live: `probe_success`, `probe_duration_seconds`, `probe_all_duration_seconds_bucket`,
  `sm_check_info` (check identity is the `job` label; `check_name` is always `http`; region
  EMEA/US/APAC). Probe names carry a `synthkit-` prefix: strip it for display with label_replace.
- Loki change lines carry src_device/dst_device as structured metadata, so a device filter is
  `{source="network-topology-exporter"} | src_device="$device" or dst_device="$device"`
  (or `| logfmt | src_device=...`).
- Existing dashboards to link to (uids): nos-noc-wallboard, nos-wan-maps, nos-topology-explorer,
  nos-network-analytics, nos-interface-performance, nos-change-and-discovery, plus the core set
  netobs-overview, netobs-topology, netobs-discovery, netobs-federation.
- Rob views in LIGHT theme: snapshot and read both `--theme light` and `--theme dark`.
