## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Owner chose new constructs over the app DSL because pipelines are batch: discrete scheduled runs with terminal states and durations, and staleness that accumulates while a stage is stalled. Engineering choice: this is a shared mechanic library (like internal/cw) that the AWS data-service constructs consume for a blueprint-declared pipeline identity and stage list, not a construct emitting new names; every emitted name stays a sourced CloudWatch or log name. Run outcomes drive real signals (Glue numFailedTasks/elapsedTime, AmazonMWAA DAGDurationSuccess/Failed and TaskInstanceFailures, SQS ApproximateAgeOfOldestMessage, Lambda IteratorAge). Add failure modes targeting a declared stage (stage_stall, run_failure) whose effect shows downstream. Add sourced CloudWatch Logs lines to Loki for /aws-glue/jobs/*, /aws/lambda/* (REPORT line) and Airflow task logs, with no payloads or record IDs. Constructs stay isolated; the new library needs an archtest allowlist entry (single-owner file).
