## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A concrete shape divergence found while scoping SKT-0006, recorded so it is not lost.

synthkit emits pod logs as Loki-native pushes to /loki/api/v1/push. The reference k8s-monitoring deployment (m7kni/rkps-awsinfra applications/k8s-monitoring/values.yaml) sets podLogsViaOpenTelemetry: true, so on that real cluster pod logs leave the collector as OTLP logs, not as Loki pushes. Both are legitimate chart configurations, and the transport changes the observable shape: OTLP logs carry resource attributes and log record attributes rather than Loki stream labels plus structured metadata.

The fidelity audit will surface this on its first run, so the decision needs to be explicit rather than emergent: does synthkit model one transport, both behind a switch, or declare the Loki path canonical and document the divergence?

This task is the decision plus whatever follows from it. It deliberately does not presuppose that emitting OTLP logs is the right answer.
