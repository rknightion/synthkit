## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
When Run:ai is the scheduler of record on Kubernetes, the failed-job and slow-job journeys start from it. Run:ai exposes a Prometheus metrics path (MetricsExporter and WorkloadExporter) plus control-plane Metrics and Telemetry APIs for data not exposed as metrics. Telemetry covers scheduler and workload state, queue depth and pending workloads, project and department quota, GPU allocation, available and idle-allocated GPUs, wait time and failures. No source emits exemplars, so the workload-to-GPU join comes from DCGM pod labels combined with Run:ai and Kubernetes metadata mapping pod to workload, project and node pool. Project and workload names can be sensitive in regulated environments and are often pseudonymised before egress, so they must stay blueprint-only.
<!-- SECTION:DESCRIPTION:END -->
